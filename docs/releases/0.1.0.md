# 0.1.0 — offline CI auditor MVP

The first release is deliberately scoped to **offline audit, saved reports and
conditional bootstrap dry-run**. It narrows the earlier full-MVP plan: controlled
lint verification ([#9](https://github.com/dnlrsls/ci-trust/issues/9)) is deferred,
not completed or silently treated as passing. Publication, source revision and
asset checksums are recorded on the
[GitHub release](https://github.com/dnlrsls/ci-trust/releases/tag/v0.1.0).

## Included

- `audit PATH`: bounded Go/npm declaration and GitHub Actions configuration
  analysis, with source-backed findings and explicit unknowns.
- `report --input FILE|-`: schema-v1 validation and deterministic human/JSON
  rendering without rescanning the repository.
- `bootstrap PATH --dry-run`: conditional, reviewable workflow proposals. No
  changes are applied; missing runtime/dependency preparation remains explicit.
- MIT-licensed project source, copyright (c) 2026 dnlrsls. Distributed binaries
  include the [applicable third-party notices](../../THIRD_PARTY_NOTICES.md)
  and unmodified license texts.

Audit/report/bootstrap do not execute repository scripts, install dependencies,
contact remote services, use credentials, change files or enforce branch rules.
Configured validation is not observed execution or efficacy. There is no aggregate
trust score. Exit 0 can include findings, FAIL, UNKNOWN or a conditional proposal;
it is not a guarantee that a project's CI works. See the [CLI contract](../cli.md).

## Install or build

Select only an OS/architecture archive listed on the release page. Verify its
SHA-256 against `SHA256SUMS`, extract it, then run `ci-trust --version`
(`ci-trust.exe` on Windows). The expected output is `ci-trust "0.1.0"`.
Archives include `LICENSE`, `THIRD_PARTY_NOTICES.md` and `LICENSES/`; no Node.js,
npm, ESLint, Docker image or candidate artifact is distributed.

For a source build, use Go 1.26 and the pinned `go.mod`/`go.sum` dependencies:

```sh
go build -trimpath -buildvcs=false -ldflags="-buildid= -X main.version=0.1.0" -o ci-trust ./cmd/ci-trust
./ci-trust --version
./ci-trust audit PATH --format json > audit.json
./ci-trust report --input audit.json --format human
./ci-trust bootstrap PATH --dry-run
```

Use output `ci-trust.exe` on Windows. Initial dependency acquisition may require
network; ordinary audit/report/bootstrap do not. Unversioned development builds
still report `dev`; the version override does not change evidence semantics.

## Verification and limits

Existing portable Go CI runs unit/public CLI tests and vet on Linux, Windows and
macOS. Its `TestVersionedBinary` builds an explicit 0.1.0 binary, checks version,
help, audit/report parity, dry-run, cold verification, rejected arguments and
unchanged owned input/counters, and prints the tested binary's SHA-256. Release
binary bytes must match the corresponding native receipt for the same source
and toolchain before packaging. Actual run/job identities and archive hashes
belong to the published release record, not an inferred cross-build claim.

These checks exercise CI Trust itself. They do not prove audited CI jobs ran,
complete test coverage, required-check enforcement or controlled ESLint success.
Checksums detect byte differences; they are not independent publisher signatures.
Binaries are unsigned; no Windows signing or macOS notarization is claimed.

## Deferred: controlled lint verification

`verify PATH --check lint` remains available as **experimental/unvalidated**.
Ordinary host invocation returns UNVERIFIABLE without executing tools; its valid
report exit 0 is not a lint PASS. The explicit protected workflow route remains
opt-in and subject to the unchanged exact-profile admission, authenticated
human consent and preflight controls. Deferral does not weaken those controls.

No real accepted CLEAN → expected FAULT diagnostic → RESTORED sequence is
claimed. Infrastructure/start failures are not sensitivity evidence. All six
acceptance criteria of #9 still apply before that feature can be called complete;
#9 remains open and is not a gate for this explicitly narrowed offline release.
