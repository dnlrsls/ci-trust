# 0.1.1 — repository boundaries and clearer offline reports

This patch improves the existing offline auditor without expanding its execution
scope. It includes the reviewed fixes from [#113](https://github.com/dnlrsls/ci-trust/pull/113)
and [#114](https://github.com/dnlrsls/ci-trust/pull/114). Publication and actual
source/run/asset identities belong to the
[GitHub release record](https://github.com/dnlrsls/ci-trust/releases/tag/v0.1.1).

## What changed

- Discovery stops before descending into a nested repository with its own `.git`
  entry, including a worktree marker. The explicitly selected root remains
  auditable, and ordinary nested packages without that marker remain included.
  Marker contents and Git-directory pointers are not followed. Intentional
  boundaries remain visible as `EXCLUDED_REPOSITORY` diagnostics.
- Conditional bootstrap can preserve an otherwise valid root proposal when a
  nested repository is outside the proposed destination. A boundary at the
  destination itself or an ancestor still blocks the draft; unsafe inspection
  and discovery-limit diagnostics remain conservative.
- Human audit/report output adds deterministic groups by exact rule and
  explanation, with escaped display text and counts of **records, not confirmed
  defects**. Every original scoped record remains in the detailed body. JSON
  schema-v1, machine output, exit codes and empty-findings output are unchanged.

A copied source tree without a repository marker is not automatically excluded.
Folder names are not an exclusion policy. See [discovery bounds](../discovery.md),
[bootstrap limits](../bootstrap.md) and the [CLI contract](../cli.md).

## Install and check

Choose an OS/architecture actually listed on the release page, verify the ZIP
against `SHA256SUMS`, extract it and run:

```sh
./ci-trust --version
./ci-trust audit PATH --format json > audit.json
./ci-trust report --input audit.json --format human
```

The expected version output is `ci-trust "0.1.1"`. On Windows invoke
`./ci-trust.exe`. Source builds can set the version explicitly with
`-ldflags "-X main.version=0.1.1"`; unversioned development builds remain `dev`.
Archives include `LICENSE`, `THIRD_PARTY_NOTICES.md`, unmodified `LICENSES/` texts
and `RELEASE.json`. No Node.js, npm, ESLint or container image is bundled.

## Verification and unchanged limits

The existing native Linux, Windows and macOS CI builds and tests the versioned
binaries, checks public CLI parity and unchanged owned inputs/counters, and runs
vet. Release distribution uses those exact retained final-main ZIPs, with
source/run bindings, actual compiler/platform metadata and binary/archive
hashes checked before publication. It does not distribute local reconstructed
cross-builds. Published checksums detect byte differences, not publisher identity;
binaries are unsigned and no Windows signing or macOS notarization is claimed.

Audit/report and bootstrap dry-run do not execute target code, install packages,
contact remote services or apply changes. Exit 0 can include findings, FAIL,
UNKNOWN and conditional proposals: it is not proof of complete coverage, correct
CI execution, validator efficacy or required-check enforcement.

The [original offline acceptance scope](0.1.0.md) still applies. Controlled lint
verification remains experimental and [#9](https://github.com/dnlrsls/ci-trust/issues/9)
is deferred, not completed or a gate for this offline patch. No accepted real
CLEAN → expected FAULT diagnostic → RESTORED sequence is claimed; no runtime
consent, admission or isolation control is relaxed by this release.
