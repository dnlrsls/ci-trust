# Closed GitHub lint composition

`PrepareGitHubReview` and `ExecuteGitHub` check the compiled gate before any
environment, clock, reader, source or service access. The exact profile now has
[source admission](lint-admission-policy.md), not runtime-plan approval. Workflow scope is fixed to Linux, the owned repository, main,
first attempt and matching run/revision/workspace; scope data is not consent.

Preparation measures recognized source and emits the canonical non-authorizing
plan only for a genuine supported declaration. Execution remeasures source and
composes exact authenticated review, protected-artifact delivery, separate image
load and three fixed owned Runner roles. No arbitrary process/runtime or imported
observations/report/admission/approval fields are accepted. Only the private
authenticated decision can create each exact role's runner Consent DTO.

Source is measured before and after image effects, including failed loads,
and around captures; Runner remeasures immediately before starting. Each role
has fresh runtime lifecycle state; only CLEAN reuses the image-loading instance.
Strict outer capture/cleanup and owned receipt decoding precede classification.
No-op FAULT is insensitive; infrastructure failures are never sensitivity passes.

The local public `Scan` route remains cold and UNVERIFIABLE, now reporting
`LINT_EXECUTION_UNAVAILABLE` rather than the historical Node hold.
Private fake-service tests cover composition, not real Docker, Node or ESLint.
The [control command and manual workflow](lint-workflow-control.md) are source
only; actual interoperability evidence remains unfinished. No dispatch,
Environment change or target execution occurs as part of source admission.
